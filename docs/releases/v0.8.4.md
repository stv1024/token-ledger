# TokenLedger v0.8.4

Released 2026-11-18. Makes requests independent of disk writes, makes agent
retirement cheap to save, reduces client refreshes, and records the Paseo 0.16
review.

## Compatibility

Requires **Paseo >=0.11.0** on both the daemon and app, as in v0.8.3. Verified
on Paseo 0.16.1. Existing `ledger.jsonl` records and `pricing.json` files are
kept and are not rewritten. On the first save, `tracker-retired.json` gets a
generation number, and later retirements go to `tracker-retired.jsonl`. If you
go back to v0.8.3, it ignores `tracker-retired.jsonl`, and agents that retired
since the last compaction restart from their last ledger record. Updating again
after that is safe: older log lines do not replace newer snapshot states.

## Changes

- **Requests do not wait for disk.** Every panel, pill, sidebar, and overview
  request waited until all queued writes were done, including a full rewrite of
  `tracker-retired.json`. On a busy daemon, requests took several seconds or
  timed out. Requests now read from memory. Turns that closed but are not in the
  ledger file yet are included, and they are not counted twice when the write
  is done.
- **Retirement appends one line.** `tracker-retired.json` holds every agent that
  ever retired, so it grows with use. It was rewritten in full each time an
  agent retired or returned. A retirement now appends one line to
  `tracker-retired.jsonl`. When the log is long, it is compacted into the
  snapshot. A return writes nothing to these files; the live journal copy wins
  on the next start. Cost baselines stay exact.
- **Stop saves data first.** The host stops a plugin that takes too long to stop.
  The tracker now saves the ledger and journal before it releases daemon
  subscriptions, and it waits at most 250 ms for timeline summaries.
- **Fewer client refreshes.** The overview and sidebar show ledger totals, not
  live usage. They refreshed on each live usage update of any agent. They now
  refresh when a turn starts or ends, or when agent details change. The pill
  and panel follow live usage at most once a second.
- **Provider configuration in the background.** After the first read, the
  30-second provider configuration refresh no longer delays requests.
- **Cached price matches.** Price matching scanned all custom and OpenRouter
  prices for each turn. Matches are now cached per provider and model until
  prices or settings change.

## Paseo 0.16

Typecheck and tests pass against the 0.16.1 SDK, and the plugin reloads on a
0.16.1 daemon. The 0.16 SDK changes the client `agents.ref` parameter, which
broke the derived agent type; this release fixes it. Paseo 0.16 adds plugin
subscriptions (`defineSubscription`, `useSubscription`), which could push
ledger changes instead of being polled. TokenLedger does not use them yet,
because they would raise the minimum to Paseo 0.16. See the
[compatibility notes](../compatibility.md).
